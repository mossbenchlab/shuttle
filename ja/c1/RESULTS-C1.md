## 読み取れること（主判定の外。この記録の範囲の事実）
- 比を算出できる 4 課題のうち、**JSON Patch が Shuttle より速いのは 2 課題**（T2・T4）、Shuttle が速いのは 1 課題（T5）、T3 はほぼ同じ（17.5 秒 対 17.3 秒）。有効 10 試行の平均は JSON Patch 19.2 秒、Shuttle 20.6 秒。
- 機械側の処理は全腕で 20 ms 未満。計測時間はほぼ全部が解答側の応答時間。
- 応答ごとの時間（有効試行）：DONE だけを返す応答でも 5.1〜13.6 秒かかっている（課題ファイルと記録ファイルを読み直す手順のため。腕ごとの平均は上の表）。この時間が「固定の起動時間」なのか、読む量に比例するのかは、この記録だけでは分けられない（J-full・W-full の DONE 応答は S・J-patch より長い傾向があるが、要因は切り分けていない）。
- Shuttle は有効 10 セル中 4 セルで 3 応答（書き込み→確認の照会→DONE）。他の腕は全セル 2 応答（提出→DONE）。
- 道具の使用回数は（N=50 の）全応答で 2〜3 回。規則外の使用を疑う回数のセルは無かった。

## 手順違反（進行役の誤り）
S-T1-50-2 と S-T6-50-2 の 2 応答目は、課題ファイルだけを読んで書かれた（応答履歴も機械の結果も渡っていない）。この 2 セルの 1 応答目を変更 A1 より前の手順で処理したため記録ファイル（transcript1）が作られておらず、それに気づかずに「transcript1 を読め」と指示して起動した。解答側は 2 セルとも同じ書き込みをもう一度提出した。
- 実際の実行では、2 セルとも解答側が付けていた `tx … at 0` により「版が古い」と拒否され、状態は変わらなかった。
- `tx` が無かった場合（外部レビューの検証による）：**T1 は数量が再加算されて誤った状態になる。T6 は `duplicate key id=900002` で拒否され、状態は変わらない。** 版検査とキー重複検査のそれぞれが働く。
- この 2 セルは無効試行とし、やり直し（S-T1-50-2：2 応答・12.1 秒、S-T6-50-2：2 応答・16.6 秒、どちらも完了）は参考記録（run-rerun/）。主判定には使っていない。元の記録（run/）は変更していない。
- 再発防止：以後は、2 応答目以降の起動前に、記録ファイルが存在し、それまでの応答数ぶんの応答と機械の結果を含むことを道具で確認する（c1.py `pre`）。

### 手順からの逸脱 D2（進行役の判断。凍結した手順と違う）
W-full の N=5,000 は、手順では「6 応答か 600 秒まで」続けるところを、各セル 3 応答で打ち切った。理由：36 応答で提出が 0、課題文が解答側の読める量を超えており、全件の書き直しは残りの応答でも成立しないと判断した。**この 12 セルは「未完了（打ち切り）」で、時間切れ・応答上限による終了ではない。**計測時間（59〜200 秒）は打ち切り時点までの値で、比較には使わない。必要なら残り 3 応答を追加実行できる（記録はそのまま続けられる状態）。

### 確認できていないこと：道具の使用回数
- 解答側には「Read と Write だけ」と指示したが、どの道具を実際に使ったかを進行役は記録から確認できない（環境が返すのは使用回数と応答時間だけ）。
- N=500 で J-full が状態を書いて受理された 6 応答は、どれも道具の使用が 8〜13 回（J-full-T2-500-1: 11、T4-500-1: 8、T4-500-2: 13、T5-500-1: 11、T5-500-2: 12、T6-500-2: 13）。W-full-T4-500-2 の 1 応答目も 12 回。長い課題文を分けて読む回数だけで説明できるかは不明。**Write は上書きしかできないため、分割して書いたなら Read/Write 以外の道具（追記・編集）を使った可能性がある。確認できていない。**道具の種類はどの腕でも記録されていないので、規則を守っていたかどうかも、守られていなかった場合に結果へどちら向きに効いたかも、全腕で未確認。
- S は全応答で 2〜3 回。J-patch は 4〜8 回。

### この記録から言えること・言えないこと
- 言える（この記録の範囲の事実）：件数を 50→500→5,000 に増やしても、S の計測時間は全規模を通して約 10.2〜53.3 秒の範囲に収まった。全文を書き直す腕は 500 件で数分かかるか完了しなかった。5,000 件の全文方式は、Weft が 3 応答まで提出ゼロで打ち切り、JSON は未実施。JSON Patch は 500 件で全セル完了したが、対象行が多い課題（T2・T3・T4）で 98〜227 秒かかった。
- 条件を添えて言える：今回の 500 件・反復 2・解答側 claude-haiku-5-5 では、S の計測時間は JSON 全文に対して T4 で約 1/14・T5 で約 1/38、JSON Patch に対して T2・T3・T4 で約 1/5〜1/7 だった（T1・T5・T6 では JSON Patch との比は 0.77〜2.89）。
- 言えない：「Shuttle は JSON の 5 倍以上速い」という一般の結論。主規模（N\*=50）では比 1.26〜2.93 で判定不能。大規模側は主判定の外で、反復 2、解答側 1 機種、道具使用の未確認事項がある。
- 追加の注意：解答側は 1 機種（claude-haiku-5-5）。同時に複数のセルを走らせており、応答時間に同時実行の影響が入っている可能性がある（腕ごとに偏らせてはいないが、打ち消せてもいない）。
